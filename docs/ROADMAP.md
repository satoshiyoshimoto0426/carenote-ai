## 3. フェーズ一覧（依存順・並行レーン明記）

### 【最優先・実装】P-PRIVACY-ORG｜事業所内で使ったときに黒塗りが成立するか ★G3b

> 検品（2026-09-12）で判明。名簿の読み出しは `lib/db/clients.ts` の `loadAliases` が3つの表すべてを
> `created_by = ログイン職員` で絞っており、`org_id` は書き込むだけで読み出しに使っていない
> （`supabase/clients_documents.sql` のコメント「org共有はフェーズ2」）。
> つまり**職員Bが、職員Aの登録した利用者の実名をメモに書くと、記号に置き換わらないまま AI へ出る**
> （型置換と漏れ検査は職員Bの名簿で行われるため止まらない）。1社＝複数職員の運用では必ず踏む。

- 🧩 **どちらかを選ぶ**:
  - (A) 名簿を org 単位に広げる（`loadAliases` を `org_id` スコープへ・記号の採番と衝突しないか・他職員の利用者が一覧に出てよいかを先に決める）
  - (B) 運用で回避する（「利用者の登録担当を1人に決める」または「担当する方は各自が登録する」）
- 👤 (B) で出すなら**事業所規程と職員マニュアルに明記**（マニュアルには 2026-09-12 に反映済: 第①章の例外④・第②章の注意とFAQ）
- 🧩 どちらでも **共有前提での黒塗り再検証**（職員2アカウントで、他人の登録利用者名が置換されるか／されないかをテストで固定）
- 👤 DATA-HANDLING-EXPLANATION.md §3 の限界に反映（2026-09-12 反映済）

## 6. 最重要リスク（2026-09-12 時点）

1. **R-LEGAL**（最大）: 録音の文字起こし事業者（Genspark 個人プラン）に DPA が無く、同社規約が機微情報を想定していない。専門家レビュー次第で**録音経路を差し替える**（スマホ録音 → CareNote → OpenAI。実装済み・切替可能）
2. **R-KAIPOKE**: 規約NG／実機NGなら転記がコピペへ縮退（2条件KPIで価値を担保）
3. **R-FIELD**: 第1・4・5・6段と拡張が**実機未確認**（第2段は実機確認済・第3段は API 疎通 HTTP 200 まで）。残りの証拠はテストとビルド ── 実機8項目が最短の解消手段
4. **R-RETENTION**: 保持期限後の自動削除が未実装（説明書で「開発中」と正直に開示中）。手動対応の運用が回るか
5. **R-KNOWLEDGE**: 知見エンジンの律速は吉本さんの言語化時間（テンプレと反映運用の固定で軽減）
6. **R-RESPONSIBILITY**: 「AIが制度準拠を判断」は保証できない → 承認データモデル＋訴求限定＋人間の最終確認で設計として担保
7. **R-ORG**（新規・2026-09-12 検品で判明）: 黒塗りが**登録した職員のアカウント内でしか効かない**。複数職員で使うと、他人が登録した利用者の実名がそのまま AI へ出る → G3b で潰すか、運用で回避したうえで規程とマニュアルに明記する（マニュアルと説明書には反映済）
