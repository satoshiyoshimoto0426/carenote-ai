# 操作マニュアル動画 制作指示書（スクリーンキャスト型）

> 対象: CareNote AI 職員向け操作マニュアルの章ごとの操作動画。
> 本文の正本は `lib/manual/content.ts`、画面は `/guide`、印刷版は `public/manual/index.html`。
> この指示書は**動画だけ**の正本。台本を直すときは本文（content.ts）との食い違いが出ないか必ず確かめる。

---

## 1. 作る動画の形式（ここは変更しない）

**実際の画面操作を録画した「スクリーンキャスト型」チュートリアル動画**で作る。

| 採否 | 形式 | 理由 |
|---|---|---|
| ✅ **採用** | **スクリーンキャスト型**（実際の画面を録画し、マウス操作とナレーションで解説） | 職員が見た画面と1対1で一致する。ボタンの位置と文字がそのまま映るので、手が止まらない |
| ❌ 不採用 | アニメーション・イラストの解説動画 | 実画面と細部がズレて「画面と違う」と迷わせる |
| ❌ 不採用 | スライド（PowerPoint）に音声を付けたもの | 操作の順番と間合いが伝わらない |
| ❌ 不採用 | 生成AIによる合成映像（架空のUI） | 実在しない画面を映すことになる。禁止 |

章ごとに1本に分け、1本は**5分以内**にする（目安は3分前後、手順の多い章でも5分まで）。迷ったところだけ見返せるようにするため。

## 2. 制作を依頼するAIへ渡す指示文（このままコピーして使う）

この指示文だけでは足りません。**この指示文と一緒に、本書の全文**（§3 収録の共通ルール・§4 納品物・§5 場面割り）を渡してください。

```text
CareNote AI（介護記録の下書き支援ツール）の操作マニュアル動画を作ってください。
一緒にお渡しする「操作マニュアル動画 制作指示書」の §3（収録の共通ルール）と §5（場面割り）に従ってください。

【形式】実際の画面操作を録画した「スクリーンキャスト型」チュートリアル動画にしてください。
架空の画面やアニメーションで再現するのではなく、実在の画面をそのまま録画します。

【収録の準備（依頼者が用意して伝えること）】
(a) 収録する CareNote の URL（開発用か、収録用の環境か）
(b) 収録専用のログインアカウント（表示名「デモ職員」・収録用ドメインのダミーメール）
(c) テスト利用者と関係者のデータ（架空の氏名で、あらかじめ登録しておく）
(d) ブラウザ拡張の読み込み元フォルダと、設定画面に入れる拡張トークン
(e) カイポケの収録用テナントとテスト利用者（本番の利用者では収録しない）
(f) 録音アプリに入れておく、収録用のダミー録音1件
(g) ⑦章のエラー画面の出し方（§5 の「エラー画面の出し方」を参照）

【作り方】
1. 下の「場面割り」の順に、書かれている画面を実際に開いて操作を録画する
2. 操作は実際より少しゆっくり行い、押すボタンの前で0.5秒ほど止めてから押す
3. 押す瞬間にマウスカーソルの位置が分かるようにする（クリック時に丸く光る設定）
4. 「ナレーション」の文をそのまま読み上げて音声を付ける（早口にしない。1分あたり300字程度）
5. 画面の文字が小さくて読めない箇所は、その部分だけ拡大して映す
6. 日本語字幕（.vtt）を必ず付ける。音を出せない場所でも読めるようにするため

【使うデータ】
テスト用の架空の利用者データだけを使ってください。実在する利用者・ご家族・事業所の
名前、電話番号、住所、生年月日、書類は、画面のどこにも映してはいけません。
ブラウザのブックマーク、他のタブの題名、通知、実在の職員のメールアドレスも映さないでください。
設定画面のトークンやパスワードは映さないでください。

【納品】
章ごとに mp4（H.264・1920x1080・30fps）と日本語字幕 vtt を1組ずつ。
ファイル名は ch1.mp4 / ch1.vtt のように章番号にしてください。
完成したファイルは `public/manual/videos/` に置きます。
```

## 3. 収録の共通ルール

- **画面の大きさ**: 1920×1080 で録画する。ブラウザは全画面にし、拡大率は 100%（左のメニューが出る幅で撮る）
- **収録アカウント**: 収録は**専用のアカウント**（表示名「デモ職員」・収録用ドメインのダミーメール）で行う。CareNote の左メニューのいちばん下には、ログイン中の職員の氏名とメールアドレスが**常に出る**ので、そこがダミー値であることを確認してから撮る
- **映してよいデータ**: テスト用の架空データのみ。実在の利用者・ご家族・事業所の情報は一切映さない
- **映してはいけないもの**: ブックマークバー、他のタブの題名、デスクトップの通知、**実在の職員のメールアドレス**、拡張機能の設定画面に入れたトークン、Supabase や Vercel の管理画面、**録音アプリの録音一覧・通話相手の名前・ファイル名・日時**
- **カーソル**: クリック時に光る設定にする。ドラッグで文字を選ぶ場面はゆっくり
- **間合い**: ボタンを押す前に0.5秒止める。画面が切り替わったら1秒待ってから次へ
- **音声**: ナレーションは台本どおり。効果音・BGMは入れない（聞き取りの邪魔になる）
- **字幕**: 日本語の .vtt を必ず同梱する
- **カイポケ画面**: 必ず**収録用のテナントとテスト利用者**で行う（本番の利用者では収録しない）。カイポケの「登録する」は
  **CareNote／拡張が自動で押すことは無く、必ず人が押す**。⑤章の台本には人が押す場面（#9・#12）が含まれるので、そこは
  「人の指で押している」ことが分かるように映す。それ以外の章では登録操作を映さない

**合計の目安: 約22分（1297秒・91場面）**

動画は容量が大きいので、**最初の1本を置く前に保管方針を決める**こと。
Git に直接入れるなら Git LFS（`.gitattributes` に `public/manual/videos/*.mp4 filter=lfs diff=lfs merge=lfs -text`）、
配信先の容量上限に収まらないなら外部に置いて `lib/manual/content.ts` の `src` を絶対URLにする。

### 公開する手順

1. 収録した `chN.mp4` と `chN.vtt` を `public/manual/videos/` に置く
2. `lib/manual/content.ts` の該当章の `video.status` を `"planned"` から `"ready"` に変える
3. `npm run manual` を実行して印刷版（`public/manual/index.html`）の案内文を作り直す
   （status が `ready` の章だけ「操作動画があります」に変わる）
4. Chrome ヘッドレスで配布 PDF を作り直す（コマンドは `tools/build-manual.mjs` の冒頭コメント）
5. `npm run build` が通ることを確かめてから公開する

`status` が `"planned"` のうちは、画面に「操作動画（約◯分）は準備中です」と正直に出る。
**録画していない動画を「ある」ことにしない。**
