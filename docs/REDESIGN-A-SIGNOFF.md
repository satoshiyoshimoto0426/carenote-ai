## 確かめたこと（ログインなしで開ける画面）

- 2026-09-23 `/sign-in`・`/sign-up`（開発サーバー・1440px と 375px）: Clerk のスタイルが `clerk` 層に入り、`lib/clerkAppearance.ts` の
  クラスが効いていることを計算後の値で確認 ── 外枠 1px `#dfe3e7`・影なし・角丸 10px、ボタンの地 `#0e5c46`、見出し 17px 太字、
  ラベル 12.5px 太字。Clerk 自身の余白（枠の中 32px 40px）は `@layer base` の全要素リセットに負けていない。375px で横にはみ出さない。
  文字はどれも読める。本番用ビルド（`npm run build`）の CSS でも、層の並び（theme → base → clerk → components → utilities）と
  これらのクラスが生成されていることを確認した。本番用サーバーでの描画そのものは見ていない（上の1の手順①でログイン画面が見える）。
- 2026-09-23 `/sign-in`・`/sign-up`（開発サーバー・375px と 1440px）: **押す・入力する部品の大きさ**を計算後の値で計測。
  直す前（375px）は入力欄・主ボタン・Google のボタンが高さ 31.4px、パスワードを見せるボタンが 40×24px、下の切り替えリンク
  （Sign in / Sign up）が高さ 19.4px だった。`lib/clerkAppearance.ts` に `min-h-11` などを付けた後は、どれも高さ 44px
  （パスワードを見せるボタンは 44×44px、切り替えリンクは 44.9×44px と 49.7×44px）。375px で横にはみ出さない。
  パスワードの入力欄は右を 48px 空け、入力した文字の終わり（右端から 48px）とボタンの左端が同じ位置で、文字がボタンの下に潜らない。
  切り替えリンクを 44px にしたとき、横の案内文（Don’t have an account?）が上に寄ってずれたので、並びの行を上下中央揃えにした
  （直した後、案内文とリンクの文字の中心の高さが一致することを計測）。
  **直せていないもの**: 下の「Secured by Clerk」の Clerk のロゴのリンク（48×14px）は、Clerk が見た目の指定の口
  （elements の名前）を出していないので、この設定では大きくできない。どうするかは上の表の **4** で吉本さんが決める
  （決まって「済」になるまで redesign/a を main へ出さない）。
