## ① 関係者名簿の表を作る ✅ 済（2026-09-14）

**これをやらないと**: 「利用者名簿を読み込めなかったため送信を中止しました」または
「関係者名簿の表が未作成のため送信を中止しました」と出て、**下書きが1つも作れません**。

1. Supabase を開く → 左のメニューの **SQL Editor**
2. `supabase/client_related.sql` の中身を**全部**コピーして貼り付ける
3. 右下の **Run** を押す
4. エラーが出なければ終わり。アプリに戻って下書きを1つ作ってみる

## ② 記号の一意制約と索引を作る ✅ 済（2026-09-14）

**これをやらないと**: 事業所で名簿を共有したときに、同じ記号（A様）の利用者が2人できても
データベース側で止まりません（アプリ側の安全網は働きますが、二重の守りにしておきます）。

1. Supabase の **SQL Editor**
2. `supabase/client_org_scope.sql` の **【手順1】の部分だけ**をコピーして貼り付ける
   （`create unique index …` から `create index if not exists client_related_org_idx …;` まで）
3. **Run** を押す

> ③④は「複数の職員で使う」ときに必要です。1人で使っている間は②まででかまいません。

---

> ⚠ **③と④は続けて同じ日に行ってください。** ③だけ先に済ませて④を後回しにすると、
> その間は「組織を選んだ職員には、まだ移していない利用者が見えない」状態になります。
> 職員が同じ利用者を二重に登録してしまい、あとから移行するときに記号がぶつかって
> 移行そのものが止まります。さらに、その窓の間に事業所を選んだ職員が利用者を登録すると、
> **その職員だけ下書きを1枚も作れなくなる**ことがあります（記号が重なるため安全側に止まります）。
> どちらの状態になっても開発者に連絡してください。

## ②-2 文字起こしを保存する表を作る（録音を使うときだけ）

**これをやらないと**: 録音の文字起こしを「記録として残す」を押したときに保存できません
（録音と文字起こし自体は、この表が無くても使えます）。

1. Supabase を開く → 左のメニューの **SQL Editor**
2. `supabase/client_transcripts.sql` の中身を**全部**コピーして貼り付ける
3. 右下の **Run** を押す
4. エラーが出なければ終わり

**保存されるもの**: 会議や面談の文字起こし**全文**。実名が入ったまま**暗号化して**保存され、
Supabase の画面から中身は読めません（読めないのが正常です）。保存から5年で消す決まりですが、
**自動で消す仕組みはまだありません**。月1回を目安に、同じファイルの【手順4】を実行してください。

## ③ 事業所のアカウント（Clerk の組織）を有効にする

**これをやらないと**: 職員Bが、職員Aの登録した利用者の名前をメモに書いたとき、
**その名前は記号に置き換わらず、そのまま AI へ送られます**。

1. Clerk のダッシュボードを開く → 左の **Organizations**
2. 組織を作る（名前は事業所名でかまいません）
3. 職員のアカウントを**全員その組織に入れる**
4. 作った組織の **ID**（`org_` で始まる文字列）を控える → ④で使います

> ⚠ 注意: Clerk は「**いま選んでいる組織**」がある職員にだけ組織IDを渡します。
> 組織に入れただけでは共有が始まりません。各職員が自分の画面で事業所を選ぶ必要があります。
> そのための切り替えは、アプリの**左下（スマートフォンでは画面の上）**にあります。
> 同じ場所に「名簿を事業所で共有中」／「名簿は自分の登録分のみ」が常に出るので、
> 職員に「ここが『共有中』になっていることを確認してから使う」と伝えてください。

## ④ いま登録済みの利用者を、事業所のものに移す

**これをやらないと**: ③をやっても、**組織を作る前に登録した利用者は共有されません**
（登録した本人にしか見えないまま＝その人の名前は他の職員のメモで置き換わりません）。

1. `supabase/client_org_scope.sql` の **【手順2】**をコピーし、
   `'org_ここを置き換える'` を③で控えた組織IDに直して **Run**
   - **0 件**なら次へ
   - **1件でも出たら④を実行せず**、その画面を見せてください（記号の振り直しが必要です）
2. 同じファイルの **【手順3】の `do $$ … end $$;` のブロック**をコピーし、
   中の `org text := 'org_ここを置き換える';` を組織IDに直して **Run**
   - エラーが出なければ成功です（「Success. No rows returned」等と出ます）。
     ※「移行しました: …」という通知文は Supabase の画面には出ないことがあります。
     成功したかどうかは、必ず次の【手順4】で数えて確かめてください
   - 赤いエラーが出たら**何も変わっていません**（安全に止まっています）。文面を見せてください
3. 同じファイルの **【手順4】**を Run して、(a) が 0 件・(b) が 3つとも 0 であることを確かめる

## 確かめ方（③④のあと・職員2人ぶんのアカウントが要ります）

1. 職員Aでログインし、利用者を1人登録する（架空の名前で可）
2. 職員Bでログインし、**利用者の一覧にその人が出ているか**を見る
   - 出ていない → ③の「いま選んでいる組織」の問題。伝えてください
3. 職員Bで「作成する」を開き、メモに**職員Aが登録した利用者の名前**を書いて
   「下書きを生成する」を押す
4. 「送る前に見る画面」で、その名前が **A様（記号）に変わっていること**を確かめる
   - 変わっていない → 共有が効いていません。**そのまま送らずに**伝えてください
