## 0. 一言で

AI が作った下書きと、そこから拾った「確かめること」を、**1か所に並べて待たせる**。
ケアマネは並んだものを見て、承認する・済みにする・不要にする。**自分から探しに行かなくてよい**状態を作る。

## 1. なぜ作るか

今は、AI が下書きと一緒に「要確認事項」「今後の予定」「アセスメントへの追記案」を出しても、**画面に出すだけで保存されない**。
画面を閉じると消えるので、ケアマネが自分でメモし直している。段階1の目的は、これを**消えない一覧**にすること。
「記録は自動・確認と判断は人」（右腕）の、最初の形になる。

## 4. 箱の形（案）

### 4.1 箱に並ぶもの

1. **下書きのままの書類**（documents の status が draft）── 承認を待っている
2. **開いているタスク**（下の 4.3 の3種類）── 済み・不要を待っている

### 4.2 どこに出すか ⏳（§6 の問1）

- **案A（おすすめ・最小）**: 利用者の区画に「確認すること」の欄を足す。その利用者の下書きとタスクだけが並ぶ。
- **案B（あとで）**: 全利用者分をまとめた「確認待ち」の画面。左のメニューに1項目足すか、利用者一覧の上に件数を出す。

まず案Aで作り、使ってみて「全員分をまとめて見たい」となったら案Bを足す。

### 4.3 タスクの種類

| 種類 | 元になるもの | 例 | 期限 |
|---|---|---|---|
| 確かめること | 各書類の要確認事項 | 「長女の連絡先が最新か確認」 | 持たない |
| 予定 | 支援経過の今後の予定 | 「10/3 14時 担当者会議」 | 予定の日時 |
| アセスメントへの追記案 | 支援経過の追記案 | 「夜間の排泄の失敗が増えた」 | 持たない |

### 4.4 流れ

1. 職員が「つくる」や録音から下書きを作り、**利用者に保存する**（T-DIR-02。保存は職員が押す）。
2. 保存と同時に、その下書きの要確認事項・予定・追記案が**タスクとして一緒に作られる**。
3. 利用者の区画の「確認すること」に、下書きの書類とタスクが並ぶ。
4. 職員がタスクごとに「済み」か「不要」を押す。誰がいつ押したかをサーバーが記録する。
5. 書類は今までどおり「承認する」を押す。承認済みになった書類は箱から出る。
6. 済み・不要にしたタスクも消さずに残し、「済んだもの」として見返せる。

AI はタスクを作るだけで、**閉じることはできない**（D4 と同じ考え方）。

### 4.5 データ（案）

新しい表を**1つだけ**足す（`tasks`）。書類の表は変えない。

| 列 | 中身 |
|---|---|
| id | タスクの番号 |
| client_id | どの利用者のタスクか |
| document_id | どの書類から作られたか（書類を消したらタスクも消える） |
| org_id | 事業所（段階1では空のまま・§6 の問2） |
| kind | 確かめること／予定／追記案 |
| text | 中身。**名前は記号にした版**（D3） |
| due_at | 予定の日時（予定だけ） |
| status | 開いている／済み／不要 |
| closed_by・closed_at | 閉じた人と日時 |
| created_by・created_at | 作った人と日時 |
| retention_until | 保持期限（元の書類と同じ・§6 の問4） |

表を作る SQL は、吉本さんが Supabase の画面で実行する（今までの表と同じやり方）。

## 5. 段階1ではやらないこと

- カイポケへ自動で書き込む（D2。最後の1押しは人）
- 通知・リマインド（メール・LINE・カレンダーへの自動登録）
- 期限の自動計算（「モニタリングは毎月」など制度から期限を作る）
- 事業所での共有（§6 の問2。Clerk の組織が有効になってから）
- チャット・ナレッジ（段階2）
- 電話の録音から、職員が押さずに下書きを作る（保存の入口ができれば、録音 → 下書き → 保存 → 箱、の流れにはそのまま乗る）

## 7. できあがりの基準（段階1の最小版）

- [ ] 「つくる」の結果を、利用者に下書きとして保存できる（T-DIR-02）
- [ ] 保存すると、要確認事項・予定・追記案がタスクとして利用者の区画に並ぶ
- [ ] 「済み」「不要」を押すと、誰がいつ押したかが残り、「済んだもの」として見返せる
- [ ] AI（サーバーの自動処理）はタスクを閉じられない。閉じるのは人の操作だけ（テストで固定）
- [ ] ほかの職員・ほかの事業所のタスクは見えない・閉じられない（テストで固定）
- [ ] タスクの中身に登録利用者の実名が入らない（テストで固定）
- [ ] DB が読めないときに「0件」に見せない（`lib/db/errors.ts` の決まり）
