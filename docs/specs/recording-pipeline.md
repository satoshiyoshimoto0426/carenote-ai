# 仕様: 録音パイプライン（アセスメント・担当者会議・モニタリング）

> 作成: 2026-09-17 / 吉本さん依頼「3帳票に録音機能を。録音→文字起こし→要約→転記を一気通貫で」を受けた段階計画（§2.8-A ①定義）。
> 承認: `~/.claude/decisions-log.md` 2026-09-17（慎重領域・§2.7-F 入口ゲート通過）。
> 先行仕様: [call-pipeline.md](call-pipeline.md)（電話の5段。本書はその第3段を対面3帳票へ広げるもの）。

## 0. 一言で

面談・担当者会議・モニタリング訪問を**その場で録り**、文字にして、今まで通り
**黒塗り → 職員が見て押す → AI → 下書き**の線路に乗せる。音声は残さない。文字起こし全文だけ残す。

## 1. なぜ作るか

いま職員は、会議のあとにメモを見ながら第4表を書き起こしている。録音があれば、会議が終わった時点で
文字は出来ていて、押すだけで下書きになる。**書く時間ではなく、聞く時間に使える**ようにするのが目的。

|---|---|---|

## 3. 動かせない事実（調査で確かめたもの）

| 事実 | 根拠 |
|---|---|
| **音声には黒塗りがかからない** | `maskPii` は文字列しか受け取らない（`lib/privacy/maskPii.ts`）。音声は黒塗りを1度も通らずに外へ出る |
| **1回に送れるのは 4.5MB まで** | Vercel Functions の受け入れ上限。実測 1MB→307 / 6MB→413（2026-09-17）。ふつうの音質で4〜5分ぶん |
| **モニタリングは録音だけでは完結しない** | `previousPlanSummary` が必須（`lib/generation/dispatch.ts:76`）。録音では埋まらない |
| **出席者の実名は黒塗りされない** | 他事業所の担当者・主治医・ご家族は関係者名簿に無い。`loadAliases` の対象外 |
| **文字は既存の3欄へ入れれば安全網が全部効く** | `assessmentNotes` / `meetingNotes` / `monitoringNotes` はトップレベルの文字列。`maskRequestBody` は入れ子を素通しする |

## 5. R1 の仕様（本PR）

### 5.1 やること

## 6. 正直な限界

- **4〜5分しか送れない**。担当者会議は R3 の区切り送信が入るまで、外で分割して入れる必要がある
- **音声は黒塗りを通らない**。録音を増やすことは、生の個人情報を外へ出す経路を増やすこと
- **出席者の実名は自動では消えない**。関係者名簿へ事前登録するか、確認画面で職員が直す
- 文字起こしサービス（米国 OpenAI）の位置づけが「予備」から「通常運用」へ変わる。説明書の改訂前に現場へ出さない

## 7. R2 の仕様（2026-09-17 実装）

### 7.1 なぜ

録音から起こした会議の文章は1〜2万字になる。確認画面は全文を1つの塊で出していたので、
**誰も読まないまま「この内容でAIに送る」を押す**ことになる。黒塗りで消せない名前
（ご家族・他事業所の担当者・主治医）を止める最後の関門はこの画面しかないので、
ここが形だけになると、仕組みは残ったまま安全だけが消える。

### 7.2 やったこと

| 直したところ | 中身 |
|---|---|
| 赤い言葉に通し番号 | 画面全体で1から連番。**同じ言葉が3回出れば3か所**と数える（種類で数えると残り2か所を見落とす） |
| 「前へ／次へ」 | 帯を画面の上に貼り付け、1か所ずつ送って確かめられるようにした。いま見ている場所は枠で囲む |
| 長い欄を畳む | 3000字を超える欄は地の文を畳み、「全文を表示する（◯字）」で開く |
| 畳んだ欄へ飛ぶとき | その欄を自動で開いてから移動する（隠れたまま飛ばさない） |
| 欄の見出し | 文字数と「この欄に赤い言葉◯か所」を出す |
| 回数制限 | `/api/transcribe` を1人1時間30回まで。押し間違い・連打・将来の区切り送信の暴走を止める |
| ルート層のテスト新設 | `/api/transcribe` はテストが1本も無かった（音声を外へ出す唯一の経路なのに） |

### 7.3 受け入れ条件

- [x] 赤い言葉の数が「か所」になり、同じ語の複数出現を別々に数える
- [x] 「次へ」で畳んだ欄が自動で開く
- [x] 長い欄が畳まれ、文字数が分かる
- [x] `/api/transcribe` が1時間30回で 429 を返し、上限後は外部サービスを呼ばない
- [x] 回数は人ごとに数える（隣の職員が巻き込まれない）

### 7.4 独立審査（2026-09-17）で直したこと

出した直後に敵対検証グラフ（6レンズ・反証投票つき）へ掛け、**critical を7件**受けた。
いずれも「テストも CI も緑のまま、安全網だけが壊れる」形だったので、同じPRで直した。

| 指摘 | 何が起きていたか | 直し方 |
|---|---|---|
| **畳むと赤い言葉が1つも出ない** | 「先頭400字だけ」にしたため、長い欄では警告記号が画面から消えていた。隠してよいのは地の文であって赤い言葉ではない | 畳んだ欄は**赤い言葉＋前後40字を全部並べる**形に変更（`candidateContexts`） |
| **全文を見ないまま送れる** | 畳んだ欄を一度も開かずに送信できた | 送る前に「まだ全文を開いていない欄が◯つ（合計◯字）」と一度だけ知らせ、「全文を開く」か「このまま送る」を選ばせる |
| **「〜の様子」を敬称と誤認** | 「入浴の様子」の「様」を敬称と取り違え、**入浴・夜間・食事**が人名候補になっていた。会議1本で数百か所が赤くなり、1か所ずつ確かめること自体が不可能だった | 敬称の直後が `子式相々態` なら数えない（`NOT_HONORIFIC_AFTER`） |
| **主治医の「◯◯先生」を1件も拾えない** | 「先生」が敬称に入っていなかった（実測でゼロ件） | `HONORIFICS` に「先生」を追加 |
| **スマホで帯が固定バーの裏に潜る** | `sticky top-2` が `.app-topbar`（固定・72px・z-index 20）に隠れ、押せなかった | `.presend-nav` を globals.css に置き、768px 未満は `top: 80px`（2026-09-23 A案の外枠で置き換え: 上の帯はどの幅でも出て、共有していない注意で高さが変わるので、`components/shell/TopBar.tsx` が測った高さ `--shell-head-h` ＋ 8px。固定の数字に戻すと `components/shell/TopBar.test.tsx` が落ちる） |
| **UI層がテストで1行も守られていない** | 仕様の [x] は自己申告だった | `react-dom/server` の `renderToStaticMarkup` で**既定の見た目**を7本テスト（jsdom 不要） |
| 回数を検証前に数えていた | 形式違い・大きさ超過でも枠を消費し、押し間違い30回で1時間使えなくなりうる | 数えるのを**外へ送る直前**に移し、上限メッセージに待ち時間を明記 |

> 厳密な上限ではない（恒久的に要るようになったら KV へ上げる）。

## 8. R3 の仕様（2026-09-17 実装・表示は切ったまま）

### 8.1 何ができるか

メモ欄の下の「この画面で録音する」から、**その場で録音**できる。
5分（または3MB）ごとに自動で区切り、**録りながら1本ずつ文字にして**メモ欄へ足す。
文字になったあとは今までどおり黒塗り →「送る前に確認」→ AI の道を通る。

| 操作 | できること |
|---|---|
| 録音を始める | 「その場の全員に伝えました」にチェックが入るまで押せない |
| 一時停止 / 再開 | 雑談・他の利用者の話になったら止める。**録らなければ外に出ない** |
| 録音を終える | 最後の区切りまで文字にしてから、マイクを離す |

### 8.2 音声をどこにも残さない作り

- 区切りは**メモリの中だけ**に置き、文字になった時点で捨てる（`blobs.current.delete`）
- 端末のディスク（IndexedDB・localStorage 等）には**書かない**。
  設計の比較検討で「端末に音声を貯める案」は、共用の事業所パソコンに黒塗り不可の
  要配慮個人情報が残るため **fatal** と判定して採らなかった
- 画面を閉じる・離れると、録音中の音声も残らず消える（マイクも離す）
- サーバにも残さない（`/api/transcribe` は受け取って外部へ渡し、返ってきた文字だけ返す）

### 8.3 落ちたときの決まり（§2.7-G のループ制御3軸）

| 軸 | 決まり |
|---|---|
| 停止条件 | 1区切りのやり直しは3回まで。**連続3本落ちたら録音ごと止める**（直らない原因のまま音声を外へ出し続けない）。録音全体は100分で自動停止 |
| 予算 | 区切りの数は最大 20本。`/api/transcribe` の1時間30回の枠に収まる（60分の会議なら12本） |
| エスカレーション | 諦めた区切りは番号で知らせる（「3本目・7本目が文字になりませんでした。その時間の内容は手で書き足してください」）。止めた理由も必ず文章で出す |

やり直しても直らない断られ方（鍵が無い・ログイン切れ・大きすぎる・形式違い）は**1回で諦める**。
送るたびに音声が外へ出るため、直らないものを繰り返し送らない。

### 8.4 なぜ「止めて始め直す」で区切るか

MediaRecorder を止めずに切った断片は、**単独では音声ファイルとして成立しない**（先頭の情報が
1本目にしか入らない）。そのまま送っても文字起こしは読めない。だから区切りごとに
いったん止めて始め直し、**それぞれが単独で送れる音声**になるようにしている。

### 8.5 現場へ出す前に必ず要ること

- [ ] **R5（事業所への説明書の改訂）と再委託先変更の事前通知**
- [ ] `NEXT_PUBLIC_CARENOTE_RECORDING=on`（既定は off。切ってある間はボタンが1つも出ない）
- [ ] 吉本さんの端末（Windows・Chrome）で、60分の会議を通して1回

### 8.6 まだ確かめていないこと（正直に）

- **実機での通し**は未実施。マイクの許可、5分ごとの区切り、区切りの継ぎ目で言葉が欠けないか、
  60分ぶんの実容量は、**動かしてみないと分からない**
- 画面を閉じる・別のタブへ移ると録音は止まる（そういう作りである）。会議中に画面を開いたままに
  できるかは運用の問題として残る
- 区切りの継ぎ目（止めて始め直す一瞬）は録れない。**0.1秒ほどの欠け**が5分ごとに入る

### 8.7 独立審査（2026-09-17）で直したこと

出した直後に敵対検証グラフへ掛け、**critical 6件**を受けた（反証フェーズは利用制限で止まったが、
どれも審査側が**実物を jsdom で動かした出力付き**で、こちらでもコードを読んで確認できた）。

| 指摘 | 何が起きていたか | 直し方 |
|---|---|---|
| **「録音を止めました」と出ても止まらない** | 画面に文字が出るだけで、MediaRecorder は `recording` のまま・マイクも掴んだまま・時計も進み続けた。止めた印を立てる側はあったが、**受け取って実行する側が居なかった** | `queue.stopped` を見て `finish()` を呼ぶ処理を追加 |
| **1本の失敗で「連続3本」になる** | 数えていたのが「試行回数」だった。やり直し上限と連続失敗上限がどちらも3なので、**1本が3回やり直しただけで必ず録音が止まった** | 数えるのを「諦めた区切りの本数」に変更 |
| **止まったあと、残りが宙に浮く** | 送られず・諦めた扱いにもならず、番号の知らせにも載らず、音声がメモリに残り続けた | 止めるときに残りを全部「諦めた」に落とす（`giveUpPending`） |
| **止まったあと画面が固まる** | 「録音を終える」を押すとボタンが1つも無い画面になり、再読込以外に戻れなかった | 終了条件に「止めた印」を含めた |
| **マイクが外れると毎秒の暴走** | 空振りのとき期限を進めていなかったため、タイマーが毎秒 `rotate()` を呼び続けた（審査の実測: 8分で122回。画面は「録音中」のまま、会議は1文字も残らず） | 空振りでも必ず期限を進める。あわせて**30秒音が来なければ「音が入っていません」と出す** |
| **やり直しが0ミリ秒で3連打** | 同じ会議音声を間を空けず3回続けて外へ送っていた。予算の式も `20区切り×3回=60` で1時間30回を超えていた | 2秒→8秒→20秒の待ちを入れた。予算は「3本諦めたら止まる」を織り込んだ式にし、回数上限と同じ場所（`lib/transcribe/validate.ts`）から参照してテストで固定 |

### 8.8 画面を動かす検査を足した

上の6件は、**純粋ロジックのテストも、描いた HTML のテストも全部緑**のまま起きていた。
動かさないと見えない壊れ方なので、`components/recording/RecordingPanel.live.test.tsx` を新設した
（jsdom＋偽の MediaRecorder／マイク／通信。パネル本体と `lib/recording` は本物）。

- 「録音を止めました」が出たとき、録音もマイクも本当に止まっているか
- 止まったあと、送れなかった区切りが番号で知らされるか
- マイクが外れても毎秒の作り直しで暴走しないか
- やり直しに間が空いているか
- うまくいけば文字が呼び出し側へ渡るか

**配線を1本外すとこのテストが赤くなることを確かめてある**（外して赤・戻して緑）。

## 9. R4 の仕様（2026-09-17 実装）

### 9.1 何が残るか

会議・面談の**文字起こし全文**。吉本さん決定 D-R3「あとで『言った・言わない』を確かめたい」。

**ここに入るのは黒塗りが効かない生の実名**（利用者・ご家族・他事業所職員・主治医）。
黒塗りは「文字にしたあと AI へ送るとき」にしか働かないため、保存するものは生の個人情報そのもの。

| 決めたこと | 中身 |
|---|---|
| 暗号化 | 利用者の実名と同じ AES-256-GCM（`lib/privacy/crypto`・鍵は `CARENOTE_PII_KEY`）。Supabase の画面から中身は読めない |
| 誰が見られるか | **親の利用者が見える人だけ**。判定は `getClientById`（org または本人）に一本化し、この表に独自の判定を持たせない |
| いつ消えるか | 作成から5年（`retention_until`）。**自動削除は未実装** ── 当面は月1回、SQL の手順4を管理者が実行 |
| 消す手段 | 画面の「消す」（開示・削除の請求に応じたと言い切れるように）＋ SQL の手順5（利用者ぶん一括） |
| AIへ | **渡さない**。復号はサーバ側の1か所だけで、用途は職員が画面で読み返すことに限る |

### 9.2 保存するかどうかは毎回その場で決める

自動では貯めない。メモ欄の下の「この文字起こしを記録として残す（任意）」で、
**保存先の利用者を選んで**押したときだけ保存する。

- 誰のものか分からない記録は、あとで探せず、請求にも応じられない
- 保存先が決まれば、見える範囲（事業所）も保存期限も自動的に決まる
- 見出しは一覧にそのまま出るので、**実名を書かない**よう画面に明記した（機械では判定できない）

### 9.4 正直な限界

- **期限切れの自動削除はまだ無い**。5年で消す決まりだけがあり、実行は手作業
- **見出しに実名を書けてしまう**。一覧は暗号化していないので、書かれたら実名が平文で残る。
  お願いと画面の注意書きで止めているが、機械では判定できない
- 一覧・本文の取得は**利用者が見えるかどうか**だけで決まる。事業所を共有していれば、
  同じ事業所の他の職員も読める（保存帳票より広い。会議録の性質上そうした）
- **実機での通し確認は未実施**（表の作成が管理者の作業のため）
