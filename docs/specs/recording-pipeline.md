## 0. 一言で

面談・担当者会議・モニタリング訪問を**その場で録り**、文字にして、今まで通り
**黒塗り → 職員が見て押す → AI → 下書き**の線路に乗せる。音声は残さない。文字起こし全文だけ残す。

## 1. なぜ作るか

いま職員は、会議のあとにメモを見ながら第4表を書き起こしている。録音があれば、会議が終わった時点で
文字は出来ていて、押すだけで下書きになる。**書く時間ではなく、聞く時間に使える**ようにするのが目的。

## 3. 動かせない事実（調査で確かめたもの）

| 事実 | 根拠 |
|---|---|
| **音声には黒塗りがかからない** | `maskPii` は文字列しか受け取らない（`lib/privacy/maskPii.ts`）。音声は黒塗りを1度も通らずに外へ出る |
| **1回に送れるのは 4.5MB まで** | Vercel Functions の受け入れ上限。実測 1MB→307 / 6MB→413（2026-09-17）。ふつうの音質で4〜5分ぶん |
| **モニタリングは録音だけでは完結しない** | `previousPlanSummary` が必須（`lib/generation/dispatch.ts:76`）。録音では埋まらない |
| **出席者の実名は黒塗りされない** | 他事業所の担当者・主治医・ご家族は関係者名簿に無い。`loadAliases` の対象外 |
| **文字は既存の3欄へ入れれば安全網が全部効く** | `assessmentNotes` / `meetingNotes` / `monitoringNotes` はトップレベルの文字列。`maskRequestBody` は入れ子を素通しする |

## 5. R1 の仕様（本PR）

### 5.1 やること

- 入力欄とその下の「録音ファイルから文字にする」を**共通部品**（`components/create/NotesField.tsx`）へ切り出す
- アセスメント・担当者会議・モニタリング・支援経過の4タブへ配る
- 文字起こしの結果を**どの欄へ足すか**を引数で受け取る（いまは `supportNotes` 固定）

### 5.2 やらないこと

- ブラウザ録音（R3）
- 全文の保存（R4）
- 確認画面の長文対応（R2）── 外で録ったファイルは今までと同じ長さなので、R1 では既存のままでよい

### 5.3 受け入れ条件

- [ ] 4タブすべてに入口が出る
- [ ] 文字起こしの結果が、そのタブの欄へ足される（他のタブの欄を汚さない）
- [ ] 上限を超えたファイルは、送る前に日本語で断る
- [ ] `app/(dashboard)/create/page.tsx` が短くなる（623行 → 500行台。§2.8-D の1モジュール500行目安へ近づける）
- [ ] 既存の「送る前に確認 → 黒塗り → AI」の経路は1行も変えない

## 6. 正直な限界

- **4〜5分しか送れない**。担当者会議は R3 の区切り送信が入るまで、外で分割して入れる必要がある
- **音声は黒塗りを通らない**。録音を増やすことは、生の個人情報を外へ出す経路を増やすこと
- **出席者の実名は自動では消えない**。関係者名簿へ事前登録するか、確認画面で職員が直す
- 文字起こしサービス（米国 OpenAI）の位置づけが「予備」から「通常運用」へ変わる。説明書の改訂前に現場へ出さない
