# 仕様: 電話連絡パイプライン（文字起こし → 黒塗り → 要約 → 支援経過・カレンダー・アセスメント）

> 根拠調査: [../CALL-PIPELINE-FEASIBILITY.md](../CALL-PIPELINE-FEASIBILITY.md)。境界は SPEC §12 を継承（**確定は常に人**）。

## 0. 一言で

電話の内容を、**建物の外に出す前に黒塗りし**、AIに下書きを作らせ、**職員が見て押してから**介護ソフト・カレンダーへ書く。

## 1. 5段階（1段ずつ動かして確かめる）

| 段 | 何ができるようになるか | 外に頼るもの | 状態 |
|---|---|---|---|
| **1. 黒塗りの強化** | 名前だけでなく、電話番号・住所・生年月日・番号類も送る前に消す。消し忘れがあれば送信を止める | なし（純粋ロジック） | **着手（本PR）** |
| 2. 送る前に見る画面 | 「AIに送る文章」を画面に出し、消し切れなかった候補を赤く示す。職員が押して初めて送る | なし | **実装済（実機確認待ち）** |
| 3. 電話の文字起こし入口 | 録音ファイルを外部サービスで文字にし、支援メモへ足して通常の「送る前に見る」へ乗せる | **D1 決定＝外部サービス（OpenAI 文字起こしAPI）**・鍵の設定 | **実装済（鍵待ち）** |
| 4. Googleカレンダー | 要約からアポイントを抽出→職員が確認→`events.insert`。タイトルは記号＋用件のみ | Google Workspace（組織内限定） | 判断待ち |
| 5. アセスメント追記（上級） | 既存本文を退避→末尾に日付つきで追記案→ビフォー・アフター承認→書込 | カイポケ実機・規程 | 後日 |

## 2. 第1段の仕様（本PR）

### 2.1 黒塗りの3段構え

```
入力テキスト
  → ① 名簿置換 maskNames（登録利用者。既存）
  → ② 型置換  maskPatterns（電話・郵便番号・メール・住所・生年月日・番号類）
  → ③ 自己点検 assertNoLeak（登録実名が1件でも残っていれば例外＝送信中止）
  → AIへ
```

- ①②を束ねる入口は `lib/privacy/maskPii.ts` の `maskPii(text, aliases)`。戻り値は `{ text, findings }`（findings は**種類と件数のみ**。原文は持たない＝ログに個人情報を残さない）。
- ③は `lib/privacy/leakCheck.ts`。`PiiLeakError` を投げ、API は **422** で「置換に失敗したため送信を中止」を返す（fail-closed）。
- 全角英数字は NFKC 正規化で半角に揃えてから照合する（「０９０−１２３４」も拾う）。

### 2.2 型置換の対象と、わざと消さないもの

| 消す | 例 | 置換後 |
|---|---|---|
| 電話番号 | 090-1234-5678 / 06(1234)5678 / 0120-123-456 | 〔電話番号〕 |
| 郵便番号 | 〒530-0001 | 〔郵便番号〕 |
| メール | a@b.co.jp | 〔メール〕 |
| 住所（番地まで） | 大阪府大阪市北区梅田1-2-3 | 〔住所〕 |
| 生年月日 | 「生年月日 1950年3月4日」「昭和25年3月4日」 | 〔生年月日〕 |
| 番号類（8〜12桁の連番） | 被保険者番号 0123456789 | 〔番号〕 |

**消さない**：予定の日付（「9月12日に面談」）。消すと第4段のカレンダー登録と支援経過の日付が壊れる。生年月日は「生年月日／生まれ／誕生」の文脈語がある場合と、昭和・大正・明治の年月日のみ対象。

### 2.5 二枚方式（吉本さん決定 2026-09-09）── 「消す」と「捨てる」は別

吉本さんの懸念「全部消すと本当に必要な情報を聞き逃す」への答え。黒塗りは**AIに見せる紙**にだけかけ、元の値は手元が覚える。

```
AIに送る紙   「A様の長女から電話。折り返し〔電話番号1〕。9/12 14時に面談希望」  ← 送信後は残さない
手元の札入れ  〔電話番号1〕＝090-xxxx-xxxx（リクエスト内のメモリのみ。ログ・DB・AIへ出さない）
AIの返事     「A様の長女より連絡。折り返し先〔電話番号1〕」
手元で戻す   「A様の長女より連絡。折り返し先 090-xxxx-xxxx」  ← 職員に返る（フル版）
```

- 札は種類ごとに連番（〔電話番号1〕〔住所1〕）。同じ値には同じ札。1リクエスト内の全フィールドで札入れを共有し、番号を衝突させない（`lib/privacy/vault.ts`）。
- AIの返事（帳票JSON）は `restoreDeep` で文字列をすべて戻してから返す。
- **名前（A様）は戻さない**：保存帳票は「記号で保持・実名を含めない」契約（`lib/db/documents.ts`）を維持。表示時の実名復元は第2段の画面で行う。
- フル版の置き場は **CareNote AI の利用者ページ**（鍵つき保管・閲覧記録）。私物の携帯メモアプリ（iCloud／Google同期）は推奨しない（安全管理措置・閲覧記録・退職時の持ち出しの3点で説明できない）。使う場合は業務用端末＋同期オフ＋規程明記が条件（上級編の範囲）。
- AIが札の形を崩した場合（括弧を落とす等）は戻らない。第2段の画面で「戻せなかった札」を表示して人が補う。

### 2.4 正直な限界（第1段では解けない）

- 名簿にない人名（家族・他事業所の担当者）は消えない → 第1b段で「関係者名簿」を追加、上級で固有表現抽出（GiNZA）
- 「お母さん」「隣の田中さん」は消えない → 第2段の「人が見る」でしか止められない
- PDF原本の実名（救済モード）は本書の対象外（別宿題）

## 2b. 第2段の仕様（実装 2026-09-09）

- `POST /api/preview`：`/api/generate` と**同じ** `maskRequestBody` を通した本文を返すだけ（AIへ送らない）。名前っぽいのに消せなかった言葉を `findNameCandidates` で候補として添える。
- `lib/privacy/candidates.ts`：敬称（さん・様・氏…）の直前と施設語尾（病院・デイサービス…）という「形」だけで拾う。続柄・役割（お母さん・ケアマネさん）は除外。**確率的で取りこぼしあり**＝置換せず「示す」だけ。上級版の固有表現抽出までのつなぎ。
- `components/drafts/PreSendPreview.tsx`：黒塗り後の本文をそのまま表示、候補を赤い下線で示す。「戻って直す」／「この内容でAIに送る」。
- `/create`：生成ボタン→ `/api/preview` → 確認画面 → 「この内容で送る」→ `/api/generate`。画面で見せた文章とAIに送る文章は同じ関数で作る。

受け入れ条件：
- [x] 候補検出のテスト（家族名・担当者名を拾う／記号と札は拾わない／続柄は拾わない／施設名を拾う）
- [x] 本番ビルド合格・tsc 合格・149テスト緑
- [x] **実機**：ログイン後 `/create` で「送る前に確認」画面が出た（2026-09-09 吉本さん実機・`POST /api/preview 200`・番号1件置換）。送信は Anthropic の残高不足で 500 → 402 に改善（残高追加後に再確認）
- [x] 名簿が読めない時は送らない（`AliasLoadError` → 503）。実機で Supabase の一時エラー "JWT issued at future" が出て名簿なしで進んだ穴を同日に根治
- [x] 名前（A様→実名）の表示時復元：`GET /api/clients/aliases`（記号→実名・ログイン職員のみ・no-store）＋ `/create` の「実名で表示／記号で表示」切替。**画面とコピーにだけ**使い、AIにも保存にも渡さない（`restoreNamesDeep` は表示専用）。実機確認は吉本さん

## 2c. 第3段の仕様（実装 2026-09-09・D1＝外部サービス）

採用：**OpenAI 文字起こしAPI**。公式ページで確認した根拠（2026-09-09）：
- Claude API は音声入力に非対応（機能一覧はテキスト・画像・PDF）→ Anthropic では文字起こしできない
- OpenAI：既定で学習に使わない／監視ログ最大30日／25MB・mp3/mp4/mpeg/mpga/m4a/wav/webm／話者分け用モデルあり／保存地域は日本を含む選択肢（条件あり）
- Gemini：**無料枠は入力が製品改善に使われ人が読む**（有料枠は使われない）→ 事故の入口になるため不採用

作り：
- `lib/transcribe/provider.ts`（差し込み口。他社へ切替可能）／`validate.ts`（形式・25MB・エラーの言い換え）
- `POST /api/transcribe`：音声を受け取り外部へ渡し、文字だけ返す。**音声は保存しない**。ログは大きさと所要時間のみ
- `/create` 支援経過の欄に「録音ファイルから文字にする」。結果は支援メモの末尾に「【録音の文字起こし】」として足す → そのまま第2段の「送る前に見る」へ（黒塗り・赤下線・人の確認）
- 鍵は `OPENAI_API_KEY`（未設定なら「設定がありません」で止まる）

説明書への影響（**要更新**）：`docs/DATA-HANDLING-EXPLANATION.md` の再委託先に **OpenAI, L.L.C.（米国・音声の文字起こし）** を追加し、「録音した音声が外部へ出る」ことを利用者・家族への説明と同意書に反映する。

受け入れ条件：
- [x] 形式・大きさの判定と、外部エラーの言い換えのテスト
- [x] tsc・biome・vitest 緑
- [x] **API疎通**：鍵設定後、合成した日本語の電話音声（約10秒・mp3）を本番と同じ呼び出しで送信 → HTTP 200・2.8秒・全文一致で文字起こし（2026-09-09）
- [ ] **実機**：`/create` で「録音ファイルから文字にする」→ 文字がメモに入る → 「送る前に確認」で番号が札になる（吉本さん）
- [ ] DATA-HANDLING-EXPLANATION.md の更新（専門家レビュー前提）
